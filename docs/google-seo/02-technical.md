# Техническое SEO

Техническое SEO отвечает на вопрос «может ли Google вообще прочитать и правильно понять
сайт». Оно не поднимает позиции само по себе. Оно убирает то, что мешает: страница,
которую робот не может открыть, не займёт место ни по какому запросу.

Статус проверен 30.10.2026 на живом сайте (`curl`) и на свежей сборке ветки `dev`.

Легенда: ✅ в порядке · ⚠️ стоит доработать · ❌ проблема · — к нам не относится

## 5. Скорость: Core Web Vitals

Три метрики, по которым Google оценивает удобство. Считаются **по реальным посетителям**
(данные Chrome, отчёт CrUX) на 75-м процентиле — у трёх четвертей визитов должно быть
не хуже порога.

| Метрика | Что меряет | Хорошо | Плохо |
|---|---|---|---|
| **LCP** — Largest Contentful Paint | Когда отрисован самый крупный элемент первого экрана | ≤ 2,5 с | > 4 с |
| **INP** — Interaction to Next Paint | Как быстро страница отвечает на нажатие (с марта 2024 вместо FID) | ≤ 200 мс | > 500 мс |
| **CLS** — Cumulative Layout Shift | Насколько «прыгает» вёрстка при загрузке | ≤ 0,1 | > 0,25 |

Важно понимать вес: скорость — это **решающий голос при прочих равных**, а не
главный фактор. Быстрая пустая страница проиграет медленной полезной. Но страница,
которая на телефоне грузится 6 секунд, теряет людей ещё до того, как они что-то
прочитают.

У маленького сайта реальных данных в Search Console может не быть вовсе: нужен
минимальный поток посетителей с Chrome. Тогда ориентир — лабораторный замер
PageSpeed Insights, но к его цифрам стоит относиться как к приблизительным.

| kartstav.cz | |
|---|---|
| ✅ в `dev` | Первый экран больше не ждёт JavaScript (коммит `51347df`) |
| ❌ на живом сайте | **Это исправление не выкачено.** На живой главной заголовок по-прежнему приходит с `opacity:0` |
| ⚠️ | ~0,5 МБ JavaScript на страницу (vendor + framer-motion + router + lightbox) |
| ⚠️ | `hero-bg.jpg` 95 КБ в JPEG, без WebP-варианта |
| ⚠️ ветка `hero-3d` | Если 3D-героя когда-нибудь вольют: `.glb` 2,8 МБ + three.js. Обязательные условия — постер-картинка как LCP-элемент, модель и three.js грузятся только после загрузки страницы (или по взаимодействию), на телефоне по умолчанию только постер, замер INP на слабом Android |

## 7. Адреса страниц (URL)

Что известно точно:

- слова в адресе — **слабый** сигнал ранжирования, но заметный для человека в выдаче;
- адрес должен быть стабильным: каждая смена — это переадресации и недели
  переиндексации (смотрите, как Search Console до сих пор переваривает `/project` →
  `/portfolio`);
- переадресации со старых адресов держать **не меньше года**, лучше всегда;
- короткий, читаемый, через дефис, без диакритики (`rekonstrukce-koupelny`, а не
  `rekonstrukce-koupelny-č1`).

| kartstav.cz | |
|---|---|
| ✅ | Короткие читаемые адреса проектов и услуг на чешском |
| ⚠️ | Разделы на английском: `/services`, `/portfolio`, `/contacts`. **Не переносить** — выигрыш меньше цены переезда. Новые страницы сразу с чешскими адресами: `/cenik`, `/o-nas`, `/services/rekonstrukce-koupelny` |

## 10. Переезд адресов: как делать правильно

На случай, если когда-нибудь всё же понадобится менять адреса (своя история уже есть):

1. Таблица соответствия «старый адрес → новый», один к одному. Не переадресовывать всё
   на главную — Google считает это soft 404.
2. Переадресация 301 (постоянная) прямо на конечный адрес, без цепочек.
3. Внутренние ссылки, canonical и карту сайта сразу перевести на новые адреса.
4. Не удалять переадресации минимум год.
5. В Search Console запросить индексирование нескольких ключевых новых адресов.
6. Неделями смотреть отчёт «Индексирование страниц»: старые адреса должны уходить в
   «Страница с переадресацией» (это нормально), новые — в «Проиндексирована».
