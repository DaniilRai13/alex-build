# Кейсы проектов: что сделано 30.10 и как запустить

## Что сделано

**Админка** (`mini-app-kartstav`):
- у проекта новые необязательные поля: часть города, тип дома, планировка, срок в
  неделях; шесть разделов кейса (как было / что хотел клиент / что сделали / сложности /
  материалы / результат); отзыв клиента; свой заголовок и описание для Google;
- у каждого фото — подпись и этап: до / в процессе / после. Сетка плиток заменена
  списком, чтобы подпись было куда вписать;
- адрес проекта в подсказках исправлен с `/project/…` на `/portfolio/…`.

**База** — новые колонки описаны в `mini-app-kartstav/database/portfolio.sql` (раздел
«Case study»).

**Сайт** (`alex-build`):
- [`fetch-portfolio.mjs`](../../scripts/fetch-portfolio.mjs) скачивает новые поля. Если в
  базе их ещё нет, пишет предупреждение и собирает сайт по-старому — деплой не падает;
- [страница проекта](../../src/pages/ProjectPage/ProjectPage.tsx): в строке фактов
  появляются часть города, тип дома, планировка, срок; кейс идёт главами, и фото каждого
  этапа стоят в своей главе с подписями; подпись становится `alt`; отзыв клиента; город
  в `<title>`; «Další realizace» сначала показывает проекты той же категории;
- пустые поля не выводятся: пока кейс не заполнен, страница выглядит как раньше.

**Черновики** — `mini-app-kartstav/database/portfolio-case-study-drafts.sql`: для всех 9
проектов подпись и этап у каждого из 80 фото, разделы «Výchozí stav», «Co jsme
udělali», «Výsledek» там, где это подтверждают фото или прежнее описание. Ничего сверх
видимого на фото и написанного заказчиком раньше — без сроков, районов, цен и сложностей.

## Как запустить — по порядку

| № | Шаг | Где | Кто |
|---|---|---|---|
| 1 | ✅ 30.10 Выполнить `database/portfolio.sql` целиком (файл можно запускать повторно — добавятся только новые колонки) | Supabase → SQL Editor | Р |
| 2 | ✅ 30.10 Выполнить `database/portfolio-case-study-drafts.sql` | Supabase → SQL Editor | Р |
| 2а | Выполнить `database/portfolio-case-study-fixes.sql` — вторая вычитка, убирает неподтверждённые «umakart» и «sádrokarton» | Supabase → SQL Editor | Р |
| 2б | Выполнить `database/portfolio-seo-texts.sql` — 4 переименования похожих проектов и свои title/description для Google у всех 9 | Supabase → SQL Editor | Р |
| 3 | ✅ 30.10 Собрать и выложить админку: `npm run build`, затем `npx netlify-cli deploy --prod --dir=dist`. 31.10 в админке поменялись названия категорий и подсказка — выложить ещё раз, когда удобно | `mini-app-kartstav` | Р |
| 4 | Вычитать чешские тексты и подписи в админке, поправить, ответить на вопросы ниже прямо в полях (необязательно до мержа: тексты содержат только факты с фото) | Админка → Portfolio → проект | З |
| 5 | Влить `dev` в `main` — сайт соберётся уже с кейсами и новой страницей портфолио | GitHub | Р |
| 6 | Запросить индексирование всех 9 страниц проектов, на следующий день — `/portfolio` | Search Console | Р |

### Страница `/portfolio` (31.10)

Было 68 слов своего текста, стало 268 (с FAQ — 420):
- title «Realizace: rekonstrukce bytů před a po – Teplice», H1 «Naše realizace – rekonstrukce bytů v Teplicích», новое описание;
- вступление в два абзаца, числа в нём считаются из данных (сколько квартир, метраж от–до, сколько с фото «до»);
- строка цифр: realizace · m² · fotografie · «před a po»;
- кнопки-фильтры заменены ссылками на три раздела: «Kompletní rekonstrukce bytů», «Kosmetické úpravy bytů», «Fasády a zateplení» — у каждого 2–3 предложения и ссылка на услугу; все проекты в HTML;
- на карточках пометка «Před a po» (где есть фото «до» и «после») и год; метки «BYT» / «Kosmetika» убраны — сайт берёт названия категорий из [`portfolioCategories.data.ts`](../../src/data/portfolio/portfolioCategories.data.ts);
- FAQ из 4 вопросов + разметка `FAQPage`.

И по всему сайту: `max-image-preview:large` на индексируемых страницах, `lastmod` для `/portfolio` и проектов в карте сайта — по дате правки в админке. В заголовке страницы проекта без своего title для Google теперь площадь: «Rekonstrukce panelového bytu – 40 m², Teplice».

**Важно:** после шага 2 черновики лежат в базе. Любая сборка сайта из `main` после
шага 5 их опубликует. Поэтому шаг 4 — до шага 5. Сам по себе шаг 2 живой сайт не
меняет: старый код новые поля не читает.

## Вопросы к заказчику

### По всем проектам

1. В какой части города каждый объект (Trnovany, Šanov, Prosetice…)?
2. Планировка до и после (2+1, 3+kk, …)?
3. Сколько недель шли работы?
4. Что неожиданного вскрылось при демонтаже и как решили? — самая ценная часть кейса.
5. Какие материалы и почему (плитка, пол, кухня, сантехника)?
6. Зачем клиент делал ремонт: для себя, под сдачу, под продажу?
7. Есть ли отзыв, который можно процитировать — с именем или инициалами?
8. У всех проектов стоит 2026 год. Это правда?

## Если что-то пойдёт не так

- **Сборка сайта пишет «the case-study columns are missing»** — не выполнен шаг 1. Сайт
  соберётся без кейсов, ничего не сломается.
- **Подпись не появилась у фото** — черновики привязаны к путям вида
  `<slug>/<имя файла>`. Фото, загруженные через админку заново, получают новое имя, и
  черновик к ним не применится — подпись вписать вручную.
- **Повторный запуск черновиков** ничего не затирает: заполняются только пустые поля.
- **Откатить админку** — копия кода до изменений лежит во временной папке
  `C:\Users\raida\AppData\Local\Temp\claude\d--alex-site\c5b31dd7-2434-4e3b-acca-9f14599c0313\scratchpad\mini-app-backup-20261030-1856`.
  Админка не под git, а временная папка не вечная — если копия может понадобиться,
  её стоит перенести. Лучше — завести для админки репозиторий.
